*`marketing-architect` reference. Read before repeating any figure. Format and discipline per `module-evidence` §4.*

## Evidence Base *(dated — re-verify before citing, Constraints 1 and 3)*

Gathered August 2026. Each row states what it does and does **not** support. Vendor and directory self-reports are labelled; they are useful and they are also marketing. Rows marked **secondary** were read in coverage rather than in the source — treat the number as a pointer to the study, not as a citation of it.

| Finding | Source | Supports / does not support |
|---|---|---|
| Hacker News launches of 138 AI/LLM repos (2024–2025): **mean** stars gained ≈121 at 24h, ≈189 at 48h, ≈289 at 7d. Distribution heavily right-skewed — **medians run far below the means**. | *Launch-Day Diffusion*, arXiv 2511.04453 | The single best anchor for "what a launch actually returns". Supports quoting a median-shaped expectation. Does **not** support quoting the mean as a typical result, and is not a causal estimate — the design is observational. |
| In the same study, the dominant predictors were the **post's score** and the repo's **pre-existing baseline stars**. A gradient-boosting model reached R²≈0.48 for 7-day outcomes from **pre-launch signals alone**. | Same study | The empirical basis for the funnel floor's ordering (`SKILL.md` §2): what the project already had outweighed where it was posted. Does not identify *which* pre-launch property does the work. |
| Posting hour mattered: an optimal window (≈12–17 UTC) was associated with roughly 200 more stars than a poor one. Weekend vs weekday was null (+10.2, p=0.81). | Same study | Supports treating timing as a real but bounded lever. Does not support any specific "best day". |
| The **`Show HN` tag showed no significant effect** (β=−119.2, p=0.39). Authors attribute the negative point estimate to selection — Show HN skews toward earlier-stage projects. | Same study | Supports refusing tag-and-format folklore. Does **not** mean the tag is harmful. |
| Study limitations, stated by its authors: observational, AI/LLM repos during a specific hype cycle, stars as the only outcome, some metadata captured post-launch. | Same study | Quote these with the numbers or quote neither. Generalizing them to a non-developer product is unsupported. |
| ≈4.5M suspected fake stars detected across GHArchive (6B+ events, Jul 2019 – Oct 2024); after strict filtering, 3.1M fake stars from 278k accounts across 15,835 repos. 91% of those repos and 62% of those accounts were deleted by Oct 2024. **The promotional effect of fake stars persisted for under two months.** | *4.5 Million (Suspected) Fake Stars in GitHub*, He et al. (Socket / CMU / NC State), arXiv 2412.13459 — a later revision is titled *Six Million…* | Supports Constraint 4: bought engagement is detected, is mostly deleted, and decays fast. Also supports treating a star count on an unfamiliar repo as unverified. |
| Reported alongside that work: of fake-star-campaign repos that appeared in package registries, ~70% had **zero dependent projects**. | **Secondary** — read in coverage of the paper, not verified against it | Points at the attention/adoption gap. Do not quote the percentage without opening the paper first. |
| An analysis of ~926k projects reported only a **weak** relationship between stars and download counts. | **Secondary** — read in commentary, primary study not verified | Supports Constraint 5 directionally. The specific figure is not citable as-is. |
| Investors and maintainers publicly treat stars as a vanity metric, preferring contributor activity (issues, comments, PRs, commits) and real usage volume; documented cases exist of a tool with far fewer stars carrying far more actual traffic than a higher-starred peer. | Practitioner and investor commentary, 2026 | Supports the attention/adoption pairing in `adoption-metrics.md` §2. It is argument and example, not measurement. |
| GitHub Trending keys on **star velocity relative to a repo's own recent rate**, not absolute count, and GitHub states there are additional undisclosed criteria. | GitHub community discussion; third-party analyses | Supports explaining why a small repo can trend. Does **not** support any method of getting onto it — the ranking is undocumented, and treating it as a target invites Constraint 4 violations. |
| Community policy, as of this sweep: r/programming removes most promotional content regardless of framing; r/webdev confines personal-project posts to a weekly thread; the sitewide 90/10 participation norm is advisory while per-community rules are enforced and may forbid self-promotion entirely. | Community rules and moderation guidance | Illustrates §3. **Never quote this row to a user as current** — Constraint 3 requires reading the live rules, and these change. |
| README structure has been studied against repository popularity — e.g. a clustering analysis of 14,901 Java repositories relating README structural patterns to stars, and ongoing work on what a good README contains for different audiences. | arXiv 2502.18440; U. Toronto README study (2022); arXiv 2603.00331 | Supports "the landing surface matters" as more than an assertion. Does **not** establish any specific README recipe as causal. |
| The widely-repeated claims that developers decide within *15 seconds*, and that a README needs *one hero image and 5–7 GIFs*, appear only in marketing content with no primary source. | Growth blogs, 2026 | **Cite neither.** The underlying point — the first screen carries the decision — stands on the studies above. The numbers are folklore, and repeating them breaks Constraint 1. |
| Claimed Hacker News launch outcomes of "5,000–50,000 visitors in 48 hours" and "1.4 stars per upvote". | Vendor marketing content | Sits well above the measured medians in row 1. Prefer the study. If quoting at all, quote it as a vendor claim and name the contradiction. |
| Claude Code plugin directories self-report large catalogs and monthly developer traffic (one directory claims 12,649 tracked plugins and marketplaces; another claims 380k+ monthly visitors across such directories). | **Directory self-reports** | Supports the existence and relevance of the evergreen directory layer (`placement.md`). The traffic figures are unaudited marketing from the party that benefits — never repeat them as measurement. |

**The pattern across this table.** The measured findings are modest and heavily caveated; the large, exciting numbers are all vendor-reported, secondary, or unsourced. That asymmetry is itself the most useful thing in the file, and it is why Constraint 1 exists.
