# Changelog

Release history for the m-skills pack. The per-skill version notes used to sit at the foot of every `SKILL.md`; they live here now so that an agent loading a skill reads instructions, not history.

## Pack releases

### V4.3 — 2026-09-06

**The design skill gets a method, and the pack gets smaller.** `design-architect` had one direction-choosing device (the visitor-mode table) and three enforcement sections, so it produced floor-clearing, anonymous output. It gains **§2 Direction** — ground in the subject, pick a named structure, derive palette and type, name the signature moment, emit a ten-line brief before any code, run the generic test — backed by three reference files: `structures.md` (21 named page and screen shapes, nine of them for Operate/Read surfaces), `palette-and-type.md` (a construction order, not a catalog), and `direction-brief.md` (the template with a filled example). Establish and Study become procedures; profile §Design carries the brief's fields; planning, implementing, and code-review ask for the direction, not only the floor. Pack-wide: version essays moved here; the measured-once load table dropped from the README; orphan monolith numbers stripped from single-section reference headings; phantom `§N` citations repointed at the files that hold them; `Guidelines §5.1–§5.4` finally labelled; header boilerplate and `Relationship to Other Skills` sections removed in favour of the hook-injected preamble and the index; descriptions rewritten as load triggers; refuse lists paired with what to do instead. The opt-in eval layer now runs the CLI with `--plugin-dir` set to the working tree, `--allowedTools Read`, and a 25-turn cap, because a skill that reads its references and the fixture project needs about 17; before, it exercised the user-wide cached release rather than the tree under test.

### Up to V4.2 — 2026-08-30

2026-08-30 | Skills V4.2 — **A second door into a branching architect.** Eight architects open by picking a route, which is exactly right when the direction is undecided and pure friction when it isn't — the user who already knows they want a decomposition had to either type the modifier longhand or answer a question they had already answered. Fourteen **route commands** in `commands/` enter one route directly: `/m-skills:decompose`, `/m-skills:rollback`, `/m-skills:ui-audit`, `/m-skills:threat-model`. They are **thin wrappers, never copies** — a command names its architect, names the one reference file that route reads, closes the alternatives, and restates not a single constraint, which is the same discipline V4.0 spent a release enforcing on the modules. **The narrowing is of route, not of rigour**: every guardrail, the git guards, and the pre-emit sweep still apply, and no route command *silently* lowers it. Curated rather than exhaustive — the modes reached by *citation* from planning and implementing mid-run (`security → harden`, `a11y → spec | build`, `docs → generate`, `design → polish`) get no command, because one would sit in the menu and never be picked. The load-bearing fix is in `skill-preamble.sh`: unresolved, `/m-skills:decompose` set the skill name to `decompose`, for which no `SKILL.md` exists — so the composition map came out **empty** and the once-per-session marker was written under a key the architect would never match, meaning the architect the command then read injected the whole preamble a **second time**. The hook now resolves a route command to its owner by grepping the command file for the `skills/<owner>/SKILL.md` path its own body already carries, so there is no static table to drift — the same reason the composition map is derived rather than tabulated. Suite grows to 558 assertions, and the new ones are the anti-rot layer: every command resolves to exactly one existing owner, the owner named in its prose matches the owner in its Read path, every reference it cites resolves, no command name collides with a skill, and **the route it forces must still appear in the architect** — so renaming a mode now fails the build instead of silently orphaning a command that points at a section nobody kept. Prior V4.1 — **The pipeline gets an ending.** The pack could make a project findable by machines (`search-optimization-architect`) and had nothing for making it findable by people, so it stopped at deploy and left the question that decides whether the work mattered to the user alone. `marketing-architect` is the seventeenth architect and the answer, organized around a **funnel floor** — positioning → artifact → placement → response → retention — whose single rule is that a failure at an earlier link cannot be bought off at a later one, which is why the skill will decline to produce a channel list while the landing surface is failing. The ordering is not a slogan: the one event study that tested these factors against each other found launch outcomes dominated by the project's pre-existing baseline and by the post's own reception rather than by the channel or the tag on it, and the tag most of the market treats as load-bearing measured as statistically insignificant. Two depths ship as **modes, not two skills** — `spread` is the light default ("where do I put this"), `campaign` the heavy door that opens by naming when it is the wrong instrument — because the eight constraints are identical at both depths and a second architect would restate all of them, which is the drift V4.0 spent a release removing. The load-bearing constraint is **rules of entry read live, never recalled**: this is the pack's only domain where a mistake is permanent, since a removed post costs a day and a ban costs the channel forever. Reuse over invention throughout — `module-handover` already owned drafts-not-actions and gains a seventh citer, `module-writing-floor` a fourth, `module-evidence` a sixth — and the new §Distribution profile section carries a **launch history** row so a community cannot be posted into twice by accident. The evidence base's most useful property is its asymmetry, stated in the file: every measured finding is modest and caveated, while every large exciting number in this market is vendor-reported, secondary, or unsourced folklore. Prior V4.0 — **The pack becomes modular.** Sixteen monolithic skill files carried the same guidance more than once and loaded all of it on every invocation. The change-propagation protocol was written three times, the OWASP sink model three times, the gate battery four — in files that drifted, which is the exact defect V3.16 spent a release fixing instance by instance rather than structurally. Now there are three tiers. An **architect** is a short spine you invoke: its constraints, its mode table, its procedure, and nothing else. A **module** is a block two or more architects would otherwise each restate, addressed **by name** because a name is the only identifier that resolves identically in a plugin install and a copied one — nine of them, hidden from the `/` menu, pointing at each other freely but never loading each other. A **reference file** is material one architect needs in only some runs, read from `${CLAUDE_SKILL_DIR}/references/` — 47 of them, so a `decompose` run never reads the PRD sections and a design polish never reads the threat model. **Constraints never move.** The Operational Constraints, the mode table, and the before-emitting checklist stay in every architect's own file, because this pack's own history is a record of rules that failed to bind when they were only prose the model had to be holding — a constraint in a file that is sometimes not read is a constraint that sometimes does not apply. The measured result is honest in both directions: the always-loaded architect floor fell from **3,660 lines to 2,240**, and narrow runs land well under their old cost (a search-optimization technical pass 332 → 222, a design polish 153 → 144) — but a run that legitimately needs three modules reads **more** than the old monolith did (a full code review on a diff touching shared shape and a security sink, 318 → 636), because it now gets the complete shared treatment instead of an abbreviated local copy that had gone stale. That is a better review, not a saving, and the README says so rather than averaging it away. The `skill-preamble` hook gains a **composition map** derived by grepping the invoked skill for the modules and reference files it names — never a static table, because a hardcoded list is one more cross-reference to rot, which is the failure the whole tier exists to remove. Ten near-identical copies of the profile-ownership protocol collapse to one line each citing Guidelines §5.1–§5.4. Suite grows to 367 assertions with the tier's own invariants: every cited module and reference file exists, every module has at least two citers, no module loads another, modules stay model-invocable and menu-hidden, and **each module's content appears in exactly one file under `skills/`** — the assertion that fails if a deleted duplicate is ever pasted back. Prior V3.16 — **The enforcement and the prose stop disagreeing.** A consistency pass found the pack contradicting itself in five places that mattered. The worst: `check-quality.sh` never read `PROJECT-PROFILE.md` — it resolved gates from `quality-gates.conf` and auto-detection — while `skill-preamble.sh` injected that output under the heading *"Resolved gates for this project (Guidelines §5)"* with the instruction *"use these verbatim, do not re-derive"*. §5 rule 1 says the profile **is** the authority, so the hook was handing Claude auto-detected commands under a file it had not opened. Resolution is now **env > profile > conf > detection**, with blank, `n-a`, and still-`<placeholder>` rows falling through rather than becoming invented commands — a half-filled profile stays safe, which is the normal state. The same fix closes two knock-ons: `guard-mutations` now guards the update command the *profile* names, and both gate caches key on the profile and manifest mtimes, so an edit invalidates them instead of a stale table outliving the session. Second: **§9 described less than it enforced.** The hook denied 22 git verbs; §9 listed six bullets, and every denial recited "staging, committing, pushing, and branching are user-only" even when it caught a `fetch`. §9 now states the actual rule — *run no git command that writes* — names what stays open (`status`, `diff`, `log`, `show`, `blame`, `merge-base`, and the listing forms), and the denial names the verb it matched. `git bisect` and `git apply` were **allowed** despite `debugging-architect` §8 claiming otherwise; they are denied now. Third: outward-facing actions became a **handover, not a confirmation**. `guard-outward` denies rather than asks, `gh` writes join the git family under §9 (read-only `gh` stays open — `code-review-architect` reviews a PR with it), and `deployment-architect` never fires a deploy, migration, publish, or rollback: it emits a copy-paste runbook — config and secrets first, then one numbered step per command with what it does and how you know it worked — while every reversible check stays open, which is what keeps the skill useful rather than merely restrictive. Fourth: `skill-preamble` runs on **every** user prompt and was spawning `jq` before checking whether the prompt was even a pack command; a shell-builtin cheap-exit removes that per-turn cost, and a once-per-skill-per-session marker ends the double injection when a skill arrived via both the slash command and the Skill tool. Fifth, the cross-reference rot: the never-weaken rule is `testing-architect` constraint **3**, cited as 5 in five places including the advisory text emitted to the model at runtime; `debugging-architect` sourced its confidence gate from a `code-review-architect` §7 that does not exist; three skills disagreed on whether a failing gate aborts the batch; and the autoprofile draft never wrote the fingerprint marker its own drift check looks for, so that signal had never once fired. Suite grows to 296 assertions, 95 of them hook behaviour, and the five load-bearing fixes are mutation-tested — including a poisoned-`PATH` probe that fails if the preamble spawns a JSON engine on an ordinary prompt, because silence alone does not prove the exit was cheap. Prior V3.15 — **The hardest rules stop being advice.** The pack's strictest guarantees were also its least enforced: §9 (no staging, committing, pushing, branching) and §10 (no auto-accepted golden update) were restated across 28 lines in 11 skill files and enforced by nothing on a fresh install — `settings.template.json` is a template the user copies by hand, and its prefix matching cannot see inside `cd x && git commit`, `git -C . push`, or `bash -c "git add ."`. Six hooks close that: three **guards** (`guard-mutations` denies git mutation, golden updates, and `rm -rf /`-class commands; `guard-outward` asks before a deploy, publish, or migration; `guard-secrets` denies writes into `.env` and key material) and three **advisories** (`skill-preamble` injects the resolved gate table and §9/§10/§15/§19 so sixteen skills stop re-deriving them, covering both the slash-command path via `UserPromptExpansion` and the auto-load path via `PostToolUse`; `warn-test-weakening` flags a newly added `.skip`/`.only`; `advise-propagation` prompts the Protocol A sweep once per shared-shape file). Three asymmetries are load-bearing: **guards fail closed, advisories fail open** — an unverifiable guard that allows is the A10 pattern Phase 4 flags; **reads are never blocked**, because §5, `deployment-architect` Phase 0, and the bootstrap hook all read the env contract, so a guard that blocked `.env.example` would break the pack itself; and **read-only git stays open**, since review and history are built on it. The deletion is the deliverable — 28 restated lines collapse to 11 cross-references, with §9 and §10 kept in full in `guidelines-meta` because they carry the *why* each denial points back at. What stayed prose is the other half of the design: the design craft floor judges a *rendered* result, §15 cannot verify a number's provenance, and a `Stop` gate that re-runs the suite until green was rejected as the open loop §16 forbids and an override of the §19 modifiers it cannot see. Test suite grows to 255 assertions, 64 of them hook behaviour including the chained-command bypasses, the `.env.example` exemption, and the opt-out re-arming. Prior V3.14 — **Security and accessibility stop being review-time attributes.** Both existed in the pack only as things checked *after* the code was written, and both were owned by a skill structurally unable to act on them: `code-review-architect` Phase 4 carries the threat model at 30 of 100 score points and **writes no code by charter**, so every vulnerability it found dead-ended, and accessibility was three lines of craft floor plus a scan, with an `<a11y>` gate in the profile that **no skill owned interpreting**. Nothing owned the sink before it was written, and nothing owned the fix afterwards. `security-architect` and `accessibility-architect` fill both ends as **auto-loadable knowledge skills** — the same class as Design and Testing, not pipeline stages — because "the code is written with these rules in mind" requires loading when the work is security- or a11y-shaped, not when someone remembers to run an audit. **The wiring is the deliverable, not the two files.** Brainstorming's grey-path list gains the trust-boundary and assistive-path questions; `planning-architect` gains constraints 8 and 9 and the `[SEC]` / `[A11Y]` step tags that sit beside `[VISUAL]`, plus `## Trust Boundaries` and `## Accessibility Contract` plan sections; `implementing-architect` applies them while writing rather than after; and Phase 4 now **verifies the commitments the plan already made** instead of re-deriving the threat model from the diff. Anchoring §1 to OWASP Top 10:2025 surfaced two categories the old checklist had no row for — **A03 supply chain** and **A10 mishandling of exceptional conditions**, the latter invisible to every scanner because fail-open code passes its tests until the day the thing it calls is down. On the a11y side, the pack covered **none** of WCAG 2.2's nine new criteria, and §3 focus management is the section that proves the split was right: an unreturned focus, a trapped dialog, and an unannounced route change each produce **zero automated violations**, so they are unreachable from a fix-the-log workflow and have to be decided at plan time. The two load-bearing constraints are honesty rules with teeth — never invent an OWASP category, a CWE, or a WCAG success criterion, because these get quoted into tickets and VPATs by people who trust them; and a green scan is never a conformance claim. Profile gains §Security and §Accessibility. Prior V3.13 — `search-optimization-architect` added; its footer entry was never written, and its rationale lives in the skill's own version line. Prior V3.12 — **Big work gets cut before it gets built.** `planning-architect` accepted a story as input but nothing in the pack produced one, so slicing large work into shippable pieces happened only in the user's head — and unsliced work is how a plan becomes a three-week branch that cannot be reviewed in one sitting or shipped in halves. `product-architect` fills it, positioned **after** the plan for its primary modes: you can only cut along seams a plan has already found, and slicing earlier produces stories that fight the architecture. `decompose` takes the first seam that holds, enforces a slice ceiling read from what the team actually merges, checks INVEST, and refuses the four ceremonial slices — setup, test-only, QA, and refactor-bundled — each of which is a way of not finishing. Its `brief`, `prd`, and `research` modes stay upstream and say so when invoked late, because a brief written after the plan is a summary and research conducted after implementation is a justification. The sourcing rule is the load-bearing correction to the prompts it replaces: every number is sourced, or written as `hypothesis` / `target` / `baseline unknown`, with no third option — a product document is specifically the artifact people quote later, so Guidelines §15 binds hardest here. Profile gains §Product Definition (tracker, priority vocabulary, AC format, slice ceiling, definition of done), with `n-a` a legitimate answer for estimating. Prior V3.11 — **Documentation stops being nobody's job.** `rolling-history` could already tell you a doc needed an edit; nothing in the pack knew how to write one, so the largest reader-facing artifact in most repos was the only surface with no craft floor. `documentation-architect` is built against the two ways docs actually fail — written *from the code outward* so they answer "what is this symbol" when the reader asked "how do I do the thing", and written once correctly and then left to drift into a confident liar that costs more than no doc at all. Hence reader-and-type selection before a word is written, a ground-truth pass that traces every command, path, flag, and symbol to a file actually read (a fabricated sample is *executed* by the reader, on their machine), one-home-per-fact drift control that treats rot as a duplication problem, and an audit mode returning a reproducible friction log plus an evidence-backed banded verdict instead of an invented grade. It is auto-loadable like `design-architect` and `testing-architect`, since doc craft is knowledge worth applying mid-task rather than a stage to remember. §6 reconciles reference docstrings with Guidelines §13 (inline comments serve a maintainer reading the body; a docstring on an exported symbol serves a caller who never opens the file). The profile gains a §Documentation Standards section — markup flavour, docstring convention, generated-reference source, fixed terminology, and what the project deliberately does not document. Release notes and migration guides live in the new skill; the changelog stays with `rolling-history`, which now hands off rather than improvising prose. Prior V3.10 — **Two skills close the last coverage gaps, and monorepos stop being ignored.** `debugging-architect` covers the pipeline's largest hole — every other stage assumed the cause was already known — and is built against the failure mode agents actually exhibit: being wrong repeatedly and confidently while changing several things at once. Hence the hard three-hypothesis ceiling, one falsifiable prediction per pass, no speculative fixes, no fixing by weakening, and separate disciplines for flakes and unreproducibles. `maintenance-architect` owns the work that previously belonged to nobody, triaging advisories by reachability and batching upgrades so a break is attributable, with an explicit ban on bundling an upgrade with a refactor. **Monorepo resolution** landed too: Guidelines §5 now says resolve the package from the paths you are touching, read its rows first, and take the **union** of constraints when a change spans packages; the profile gained a §Packages table and the hook enumerates workspace packages instead of merely noting that a monorepo exists. Prior V3.9 — **The pack tests itself, and notices when the profile lies.** Two gaps closed. (1) `tests/run-tests.sh` — 89 dependency-free assertions across structure, script behaviour, and an opt-in model-in-the-loop eval layer; **mutation-tested**, so reintroducing the `eval`/`find` bug, the wrong pnpm audit flag, or a dropped `disable-model-invocation` each make it fail. `claude plugin eval` will replace the third layer when it ships; it is absent from 2.1.158. (2) **Profile drift detection** — the hook previously fired only when the profile was *missing*, never when it was *wrong*, which is the worse case because the skills trust that file. It now verifies the profile's claims against the repo: every backticked `<pm> run <script>` must still exist in the manifest, every path must still resolve, and a cksum fingerprint of the manifest/docs/deploy-config inputs detects changes underneath it. A date is deliberately **not** the signal — an old profile can be accurate and a new one can already be wrong. Silence stays the common case, and template placeholders, version strings, and `pending` rows are guarded against false alarms. Prior V3.8 — **Greenfield gets an entry point.** V3.6–3.7 taught the pack to defer unknowable rows and to investigate existing repos, but left a brand-new project with nowhere to start: the hook correctly declined to interrogate the user, and then offered nothing. `brainstorming-planner` gains **Kickoff Mode** — the greenfield entry point, run as a conversation rather than an intake form (five questions maximum before it starts proposing, because a wrong default is cheap to change on day one). It establishes what is being built and the smallest genuinely useful slice, **routes each foundational decision to the skill that owns it** rather than deciding centrally, defers the rest as `pending` with deferring as the explicit default, seeds only the rows the conversation actually settled, and ends by pressure-testing the first slice. The SessionStart hook now offers that conversation on a greenfield project instead of saying nothing, and declining remains a first-class outcome. Prior V3.7 — **Brownfield: investigate, then ask.** V3.6 made the profile progressive but left existing projects under-served — rows whose answers sit in the repo were being deferred to `pending` or asked about. Guidelines §5.3 now states the rule: on an existing codebase almost every row is answerable (design system in the components and token files, placement in the test tree, shipping in the deploy config and CI workflow, config contract in the env example), so **exhaust the repo first and ask only what the code cannot say** — intent, who may fire production, where secrets live, the rollback they would really perform. Asking a question the repo already answers is a defect, as is deferring a row from a file nobody opened. The SessionStart hook gained a structural sweep (repo shape, test count and placement, styling/token files, deployment config across nine platforms, CI deploy workflows, env contract) and now hands Claude pointers rather than conclusions; `deployment-architect` Phase 0 gained a row-to-file table naming what usually answers each §Deployment row. Fixed a real bug found in testing: the detection `find` used `eval`, which re-parsed escaped parens and silently reported zero tests in a repo that had them. Prior V3.6 — **The profile became progressive.** It was previously treated as a one-shot artifact gathered at install, which is wrong for most of its content: a project with no UI has no design system, one that has never shipped has no rollback mechanism, an empty repo has no commit convention. Now each section is **owned by the skill that needs it** and filled on that skill's first run, in at most 3–4 questions, never front-loading questions for work that isn't happening. Unknowns carry an explicit state — `n-a`, `TODO`, `pending: <when>`, or `assumed: <value>` — so a blank or invented row is a defect. Greenfield projects get **decisions rather than detections**: the bootstrap hook recognises a not-yet-started project (fewer than three source files, `node_modules` excluded) and deliberately does not interrogate the user, while `design-architect` gains an **Establish** mode that decides the visual world instead of matching one that does not exist — guarded by the rule that a missing design doc is not proof of greenfield, since starter scaffolding is still evidence of intent. Prior V3.5 — **Deployment Architect closes the pipeline.** New skill covering the stage where a green pipeline proves the least: it resolves hosting model, environments, deploy and rollback mechanisms from a new Project Profile §Deployment, then works through a readiness gate and a pre-flight risk pass organised around the four failure classes CI cannot see — per-environment config, pre-existing data, caches that outlive the deploy, and no way back. The rollback plan is a hard gate written *before* deploying and must name its one-way doors (migrations, sent mail, charges, client-side caches). Deploying, publishing, migrating shared state, and rotating secrets are treated as outward-facing actions requiring confirmation per environment; release tags stay user-only like every other git write. README's source attributions were unified into one table with every link and license verified against the actual repositories — which corrected `code-simplifier` from a plugin to an agent inside `pr-review-toolkit`, and removed a license claim from `caveman`, which declares none. Prior V3.4 — **Absorption, not inventory.** The `i-have-adhd` skill added in V3.3 is removed as a standalone command and folded entirely into Guidelines §17, which now carries the complete ruleset including the forbidden opener/recap/closer lists. Rationale: an output style is influence, not something to remember to invoke — and the pack exists to keep the command surface small, so a source that fills a blind spot belongs inside the skill that had the blind spot. The session-wide hook now extracts §17 from `guidelines-meta` rather than reading a separate skill file. Skill count back to 8. README's sources section restructured around what each source was folded *into*. Prior V3.3 — **i-have-adhd incorporated as a skill.** [ayghri/i-have-adhd](https://github.com/ayghri/i-have-adhd) (MIT) was previously absorbed only as the *shape* of Guidelines §17; it now also ships as the standalone, toggleable `i-have-adhd` skill carrying the full source: the five cognitive facts behind the rules, all ten rules with their worked examples, the six break-the-rules cases (including the two §17 had dropped — a rule that would delete the answer, and a rule that fights the harness), and the pre-send check. §17 gained the pre-send check, the fewest-steps rule, the mid-work-question nuance, and the harness clause. A second `SessionStart` hook (`scripts/adhd-always-on.sh`, ~25ms, opt-in by flag file) re-injects the ruleset on `startup|resume|clear|compact`, so the toggle survives the context clear where a session-only setting silently lapses. README's provenance section rewritten into a full sources table naming each upstream project, its license, where it lives here, and exactly what was taken. Prior V3.2 — **Self-setup.** Adds a `SessionStart` hook (`scripts/profile-bootstrap.sh`) that detects a project's package manager, resolved gate commands, framework/UI/test/i18n hints, docs, commit config, and CI the first time you open a project with no `PROJECT-PROFILE.md`, then hands Claude verified values to build one from. Silent when the profile exists, in non-project directories, and after one decline (`.claude/.m-skills-no-bootstrap`); writes nothing unless `M_SKILLS_AUTOPROFILE=1`. `Setup` wired to the same script for `claude --init` in CI. `check-quality.sh` detection reduced to a single process spawn so the hook costs ~0.2s. Prior V3.1 — **Plugin release.** The pack is now a single-plugin marketplace (`.claude-plugin/plugin.json` + `marketplace.json`, validated with `claude plugin validate --strict`), so commands install once as `/m-skills:<name>` and can never collide with a bundled or project skill. Invocation control added per skill: pipeline stages are user-triggered only, knowledge skills stay auto-loadable, `guidelines-meta` is hidden from the menu. Guidelines gains **§19 Invocation Modifiers** — a shared plain-language vocabulary ("tests later", "skip gates", "fix the findings", "proceed") so the same phrase behaves identically in every skill, with the rule that a modifier narrows scope but never the honesty bar and never unlocks git. Cross-references switched from hardcoded `.claude/skills/…` paths to skill names, and `check-quality.sh` is now addressed via `${CLAUDE_SKILL_DIR}`, so both install modes work unchanged. Prior V3.0 — **Portability release.** Every skill genericized off one project and onto the Project Profile indirection layer (Guidelines §5): commands resolve as roles (`<lint>`, `<test>`, `<build>`…), framework mandates became "the project's committed conventions", and hard-coded doc paths became a profile table. Concrete examples are now explicitly labeled disposable illustrations of a category, so the pack doesn't rot into a catalogue of one codebase's field names. New **Design Architect** skill distilling impeccable + hallmark. Guidelines gains §15 Honest Output, §16 Bounded Verification, §18 Pre-Emit Self-Critique, and a rewritten §17 Reply Protocol carrying the i-have-adhd shape. Code Review gains a fifth scored dimension (Design Craft) and a consolidated change-propagation audit. `check-quality.sh` rewritten to auto-detect gates across npm/pnpm/yarn/bun, Make, Python, Rust, and Go. Prior V2.7 — skills restructured into `skills/<name>/SKILL.md` with frontmatter; V2.6 — official plugins absorbed; V2.5 — ponytail + caveman absorbed

## Per-skill version notes

### accessibility-architect

v1.0 — New skill. Accessibility was the pack's thinnest coverage relative to its consequences: contrast and focus-visible in `design-architect`'s craft floor, a scan and a keyboard walk in `testing-architect`, and an `<a11y>` gate in the profile that **no skill owned interpreting**. Nothing covered semantics, focus architecture, or announcement, and nothing covered a single one of WCAG 2.2's nine new criteria — including SC 2.5.8's 24×24 target size and SC 2.5.7's drag alternative, both of which a competent team ships without ever hearing about. Built as an auto-loadable knowledge skill so it loads when the work is interactive, which is what "created with these rules in mind" requires. Focus management is the load-bearing part — now `module-operability-floor` §2 — and the reason this could not have been folded into `design-architect`: focus traps, unreturned focus, and unannounced route changes produce **zero automated violations** because there is no violating node, so they are unreachable from a fix-the-log workflow and have to be decided at plan time. Constraint 4 — every barrier names who it blocks — is what stops the rules from being negotiated, and Constraint 3 is what stops a green scan from becoming a compliance claim.

### brainstorming-planner

v2.0 — Genericized: project-specific stack/UI mandates replaced by a Project Profile read (Guidelines §5); the emitted prompt now carries resolved stack, gates, and reuse paths as filled placeholders instead of hardcoded framework rules. Adds a pre-brainstorm history skim, Inversion + cost-of-being-wrong to the critique frameworks, grey paths promoted to a required output block, explicit non-goals as a first-class section, a Design Architect hand-off for UI-facing ideas, and the no-invented-facts guardrail. Prior v1.8 — YAGNI + one-liner preference named in guardrails and the emitted prompt; handoff target named; Guidelines and Testing Architect cited

### code-review-architect

v2.0 — Genericized: gates, conventions, doc targets, and blind spots resolve from the Project Profile (Guidelines §5); framework-specific review rows (utility-CSS purge, one framework's change detection, one API doc) replaced by stack-neutral equivalents. Threat model restated by sink category rather than by one app's shape, keeping prototype pollution, IDOR, path traversal, and the policy-declared-in-two-places blind spot. Adds a fifth scored dimension, Design Craft, sourced from the new Design Architect (re-weighted away when the diff has no UI), a consolidated change-propagation audit covering shape/API/origin, the no-estimated-numbers rule, and a verdict-first output shape. ### debugging-architect

### maintenance-architect

v1.0 — New skill owning the work that previously belonged to nobody: dependency health, advisories, deprecations, and rot. Built around three rules that make maintenance safe rather than merely done — never bundle an upgrade with a refactor (mixed diffs destroy bisectability), one batch/one class/one revert with the lockfile as the rollback, and triage by **reachability** rather than headline severity, which is the honest question and forbids both performing urgency and dodging work. Phase 5's rot sweep covers what no gate reports because nothing fails: suppressions, permanently-skipped tests that masquerade as coverage, unused dependencies, dead code, stale TODOs, and doc drift. Deliberate non-upgrades are recorded in the Project Profile with a revisit condition so they are decided once rather than re-litigated.

### marketing-architect

v1.0 — New skill. The pack could make a project findable by machines and had nothing for making it findable by people, so the pipeline ended at deploy and the question that decides whether the work mattered went unanswered. Built from an August 2026 evidence sweep, and its organizing idea is §2's funnel floor: five links in order, where an early failure cannot be bought off with more volume later. That ordering is not a slogan — the one event study that tested these factors against each other found a launch's outcome dominated by the project's pre-existing baseline and by the reception of the post, not by the channel or the label on it, which is links 1, 2, and 4 outweighing link 3. Hence a skill that will decline to produce a channel list, and hence §1's audience table before any channel is named. The two depths the user asked for are modes, not separate skills: `spread` is the light door and the default, `campaign` the heavy one that opens by saying when it is the wrong instrument — one spine, because the constraints are identical at both depths and a second architect would restate all eight. Constraint 3 exists because this is the only domain in the pack where a mistake is permanent: a removed post is a bad day, a ban is the channel gone for good, so no community is ever recommended from memory. Constraint 5 and the dated evidence base exist because attention and adoption diverge routinely, and the market that sells the former measures it in the numbers that are easiest to buy.
